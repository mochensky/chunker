# chunker

Быстрый пре-генератор миров Minecraft: Java Edition с веб-интерфейсом. Генерирует чанки сервера или одиночного мира заранее, чтобы игроки не ждали загрузки рельефа, а сервер не тратил такты на генерацию.

Поддерживаемая версия: **Minecraft 26.3**.

## Возможности

- **Те же чанки, что у ванилы** — рельеф, пещеры, руды, деревья, все структуры и мобы структур (жители, пиглины, утопленники и остальные, со снаряжением) генерируются блок в блок так же, как это делает ванильный сервер. Генерацию выполняет библиотека [chunker-worldgen](https://github.com/mochensky/chunker-worldgen), которая проверяется по настоящим классам сервера.
- **Скорость** — больше тысячи чанков в секунду на современном настольном процессоре, с загрузкой всех ядер. Сервер и Chunky обычно генерируют 100–300 чанков в секунду.
- **Веб-интерфейс** — живая карта мира (рельеф и биомы), выбор области мышью, прогресс, скорость и оставшееся время. Работает одинаково на домашнем компьютере и на VPS или хостинге.
- **Любая область** — квадрат, круг или прямоугольник вокруг любой точки, в Верхнем мире, Незере или Энде.
- **Оценка размера** — число чанков, место на диске и время до запуска; место на диске измеряется на пробных чанках выбранной области.
- **Пауза и продолжение** — задачу можно приостановить, продолжить и отменить. После перезапуска программы она продолжается с того же места.
- **Существующие чанки не трогаются** — уже сгенерированные чанки никогда не перезаписываются.
- **Режим «только рельеф»** — примерно на треть быстрее; структуры и фичи сервер расставит сам при первой загрузке чанков.
- **Датапаки** — датапаки мира учитываются в порядке из `level.dat`.
- **Безопасность мира** — chunker блокирует мир (`session.lock`) так же, как сервер, и не запускает генерацию, пока сервер работает.
- **Один файл** — один бинарник без зависимостей. Jar ванильного сервера с данными игры ищется в папке сервера или скачивается у Mojang.
- **Русский и английский** — язык интерфейса переключается.

## Требования

- Мир Minecraft 26.3: папка сервера или папка одиночного мира. Мир должен быть уже создан (запустите сервер один раз).
- Во время генерации сервер должен быть остановлен.
- Доступ в интернет при первом запуске, если в папке сервера нет jar сервера (он скачивается у Mojang, около 60 МБ).
- Rust 1.90+ (только при сборке из исходников; для готовых бинарников не нужен).

## Установка

### Вариант 1: Скачать готовую сборку (рекомендуется)

Перейдите на [страницу релизов](https://github.com/mochensky/chunker/releases/latest) и скачайте бинарник для вашей ОС:

- `chunker-windows-amd64.exe` — Windows
- `chunker-linux-amd64` — Linux (x86-64)
- `chunker-linux-arm64` — Linux (ARM64)
- `chunker-macos-arm64` — macOS (Apple Silicon)

Сборки для Linux статические и запускаются на любом дистрибутиве.

### Вариант 2: Собрать из исходников

```bash
git clone https://github.com/mochensky/chunker
cd chunker
cargo build --release
```

Бинарник — `target/release/chunker` (`chunker.exe` на Windows).

## Начало работы

### Шаг 1: Остановите сервер

chunker записывает region-файлы мира напрямую, поэтому сервер не должен работать одновременно с ним. Если сервер запущен, chunker показывает это и не начинает генерацию.

### Шаг 2: Запустите chunker в папке сервера

Положите бинарник в папку сервера (где лежит `server.properties`) или в папку мира (где лежит `level.dat`) и запустите его.

**Linux:**

```bash
chmod +x chunker-linux-amd64
./chunker-linux-amd64
```

**Windows:** запускайте из командной строки, чтобы окно не закрылось и была видна ссылка:

```cmd
cd C:\path\to\server
chunker-windows-amd64.exe
```

Можно запустить и из любого места, указав папку явно: `chunker --path /path/to/server`. Без папки веб-интерфейс предложит выбрать мир: он показывает миры, найденные рядом и в `.minecraft/saves`, и позволяет выбрать папку вручную.

При запуске вы увидите:

```
INFO chunker::web: web UI: http://localhost:8730/?token=3f9c1a...
```

### Шаг 3: Откройте веб-интерфейс

Откройте ссылку в браузере. На VPS замените `localhost` на адрес сервера. Токен в ссылке выполняет вход; браузер его запоминает.

### Шаг 4: Выберите область и запустите

1. Выберите измерение.
2. Кликните по карте, чтобы поставить центр, или введите координаты.
3. Задайте радиус или выберите готовый вариант. Контур на карте можно тянуть мышью, чтобы изменить размер. Shift + перетаскивание рисует прямоугольник.
4. Выберите, что генерировать: всё или только рельеф.
5. Проверьте оценку (чанки, место на диске, время) и нажмите **Начать генерацию**.

Во время работы задачи карта показывает сгенерированные чанки. Когда задача завершится, запустите сервер: сгенерированная область будет уже готова.

## Командная строка

Веб-интерфейс запускается по умолчанию. Генерация работает и без него:

```bash
# Квадрат 2048x2048 блоков вокруг 0,0 в Верхнем мире
chunker --path /path/to/server generate --radius 1024

# Круг в Незере вокруг точки
chunker --path /path/to/server generate --dimension minecraft:the_nether --center 500,-200 --radius 512 --shape circle

# Прямоугольник: по 1024 блока в каждую сторону по X, по 256 по Z
chunker --path /path/to/server generate --shape rectangle --radius 1024 --radius-z 256

# Только рельеф
chunker --path /path/to/server generate --radius 1024 --terrain-only

# Информация о мире
chunker --path /path/to/server info
```

В веб-интерфейсе незаконченная задача продолжается кнопкой **Продолжить**, в том числе после перезапуска. В командной строке запустите тот же `generate` ещё раз: уже сохранённые чанки будут пропущены.

### Параметры

| Параметр | Описание |
|---|---|
| `-p, --path <папка>` | папка сервера или мира (по умолчанию текущая папка) |
| `--server-jar <файл>` | jar сервера, из которого читаются данные игры (ванильный, bundler или `cache/mojang_*.jar` от Paper) |
| `--cache-dir <папка>` | где хранятся скачанный jar сервера и токен доступа |
| `--offline` | никогда не скачивать jar сервера |

`serve` (веб-интерфейс):

| Параметр | Описание |
|---|---|
| `--host <адрес>` | адрес, на котором принимать подключения (по умолчанию `0.0.0.0`; `127.0.0.1` — только локальный доступ) |
| `--port <порт>` | порт (по умолчанию `8730`) |
| `--token <токен>` | токен доступа (также переменная `CHUNKER_TOKEN`); если не задан, создаётся случайный |
| `--no-auth` | без токена; только для доверенной сети |

`generate`:

| Параметр | Описание |
|---|---|
| `--dimension <id>` | `minecraft:overworld` (по умолчанию), `minecraft:the_nether`, `minecraft:the_end` |
| `--center <X,Z>` | центр в блоках (по умолчанию `0,0`) |
| `--radius <блоки>` | радиус в блоках; у прямоугольника — по X |
| `--radius-z <блоки>` | радиус прямоугольника по Z |
| `--shape <форма>` | `square` (по умолчанию), `circle` или `rectangle` |
| `--threads <n>` | число рабочих потоков, `0` — все ядра (по умолчанию) |
| `--terrain-only` | только рельеф; структуры и фичи сервер расставит позже |

## Токен доступа

Веб-интерфейс запрашивает токен. Он печатается при запуске в ссылке `/?token=...`. Если `--token` не задан, chunker один раз создаёт случайный токен и хранит его в папке кэша, поэтому между запусками он не меняется:

- Windows: `%LOCALAPPDATA%\chunker\token`
- Linux и macOS: `~/.cache/chunker/token` (или `$XDG_CACHE_HOME/chunker/token`)

> **Важно:** любой, у кого есть токен, может запустить генерацию в вашем мире. Не публикуйте ссылку. На VPS можно принимать подключения только на `127.0.0.1` и открывать интерфейс через SSH-туннель: `ssh -L 8730:127.0.0.1:8730 user@your-server`.

## Развёртывание на VPS / сервере

### 1. Загрузите бинарник на сервер

```bash
scp chunker-linux-amd64 user@your-server:/opt/minecraft/
ssh user@your-server
chmod +x /opt/minecraft/chunker-linux-amd64
```

### 2. Остановите сервер Minecraft и запустите chunker

```bash
cd /opt/minecraft
./chunker-linux-amd64
```

Откройте напечатанную ссылку, подставив адрес своего сервера. Если порт `8730` закрыт в файрволе, откройте его или используйте SSH-туннель из раздела выше.

### 3. Работа после отключения от SSH (необязательно)

Задача выполняется, пока работает chunker. Чтобы закрыть SSH-сессию во время долгой генерации, запустите chunker в `screen` или `tmux` либо как сервис systemd. Создайте файл `/etc/systemd/system/chunker.service`:

```ini
[Unit]
Description=chunker
After=network.target

[Service]
Type=simple
User=minecraft
WorkingDirectory=/opt/minecraft
ExecStart=/opt/minecraft/chunker-linux-amd64 --path /opt/minecraft
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl start chunker
sudo journalctl -u chunker -f
```

Перед запуском сервера Minecraft остановите chunker: `sudo systemctl stop chunker`.

## Как это работает

- chunker читает `level.dat`, настройки генерации мира и его датапаки, а данные игры — из jar ванильного сервера.
- Чанки генерируются по регионам, сначала ближайшие к центру, на всех ядрах процессора.
- Сгенерированные чанки сохраняются со статусом `features`: рельеф, структуры и фичи готовы. Когда сервер их загружает, он только добавляет свет и первых животных, так же как после собственной генерации.
- Прогресс хранится в `<мир>/.chunker/job.json`, превью карты — в `<мир>/.chunker/preview/`. После генерации эту папку можно удалить.
